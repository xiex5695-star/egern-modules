# Egern Modules

个人使用的 Egern 独立模块维护仓库。

## 原则

- 一个应用 / 功能一个模块，**不做去广告合集**。
- 优先采用仍维护且许可证允许修改、再发布的上游开源项目。
- 保留来源、许可证、修改记录；没有明确再分发许可的第三方代码不直接公开复制。
- MITM 只写必需域名，尽量避免读取 Cookie、Token 或提交隐私数据。
- 稳定版在 `main`，上游更新先人工审查，测试后再提交；禁止自动替换已发布脚本。
- 任何模块在 Egern 真机测试通过以前，均不标为“可用”。

## 目录

- `modules/`：单独的 Egern YAML 模块。
- `scripts/`：仅放有授权的、经过审查的脚本。
- `rules/`：独立规则。
- `upstreams.json`：需要跟踪的上游文件与已审查的 Git 提交 SHA。
- `.github/workflows/`：每周检测上游变化和本仓库 JS 语法；不会自动合并。
- `tools/check_upstreams.py`：只读取公开 GitHub API，不执行上游代码。

## 引入一个插件的步骤

1. 确认原始仓库、实际插件文件、许可证和最近真实维护记录。
2. 核对是否有涉及 HTTPS 解密、Cookie、账号或设备信息的敏感逻辑。
3. 在 `modules/` 新建单应用模块；必要时将获许可的脚本放入 `scripts/`。
4. 在 Egern 中单独开启并测试，避免与原模块同时启用。
5. 审核通过后才将文件列为稳定可订阅版本，并在 `upstreams.json` 登记上游（用于更新提醒）。

## 订阅格式

公开仓库里的独立模块可通过以下地址导入 Egern：

`https://raw.githubusercontent.com/xiex5695-star/egern-modules/main/modules/<name>.yaml`

替换 `<name>` 为实际存在的模块文件名。当前**尚无已发布插件**，请勿把示例链接当成可用模块。

## 安全提醒

不要上传个人完整代理配置、节点、Cookie、Token 或含密码的日志。自动检查只能辅助发现变化，不能证明插件安全，也不能代替手机上的效果测试。
